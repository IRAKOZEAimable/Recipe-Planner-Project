# Recipe Planner

Recipe Planner is a browser-based meal dashboard built with HTML, Tailwind CSS, and vanilla JavaScript. It combines login authentication, recipe statistics, recipe cards, search and filtering, and an add-recipe form in one central page.

The application does not use a backend, database, framework, or real URL routing. Everything runs locally in the browser.

## Final application

The main application is:

```text
dashboard.html
```

This single HTML file contains two views:

1. A login screen
2. The recipe dashboard

The login screen is displayed first. When the entered email and password match a user in the `users` array, JavaScript hides the login view and reveals the dashboard view using the DOM.

Logging out performs the opposite operation. It hides the dashboard, displays the login screen, resets the login form, and focuses the email field. No second page is loaded and the browser URL does not change.

## Features

### Demo login

The login form:

- Accepts an email and password.
- Normalizes the email by trimming whitespace and converting it to lowercase.
- Searches the `users` array for matching credentials.
- Displays an inline error when the credentials do not match.
- Clears and focuses the password field after a failed login.
- Opens the dashboard without routing after a successful login.
- Returns to the login screen when the user clicks **Log out**.

Available demo accounts:

| Name | Email | Password |
|---|---|---|
| Alex | `alex@example.com` | `recipe123` |
| Maya | `maya@example.com` | `meal456` |
| Sam | `sam@example.com` | `food789` |

> This is demonstration-only authentication. The credentials are stored in the browser source and are not secure enough for a production application.

### Dashboard statistics

The dashboard calculates three values from the complete recipe array:

- Average preparation time
- Total calories
- Number of vegetarian recipes

The original 15 recipes produce:

| Statistic | Initial value |
|---|---:|
| Average preparation time | 21.0 min |
| Total calories | 5,040 |
| Vegetarian recipes | 10 |

The values are generated by JavaScript instead of being hard-coded into the page.

### Recipe cards

Every recipe is displayed as a responsive card containing:

- Recipe name
- Category
- Preparation time
- Calories, when available
- A green **Vegetarian** label when `isVegetarian` is `true`

The grid automatically adjusts the number of columns based on the available screen width.

### Search and filtering

Users can filter the recipe list using:

- A live name search
- A category selector
- A vegetarian-only checkbox

All three filters work together. The heading above the cards displays the number of matching recipes.

If no recipes match, the page displays a **No recipes found** message.

### Adding recipes

The **Add a new recipe** form accepts:

- Name
- Category
- Preparation time in minutes
- Calories
- Vegetarian status

When the form is submitted:

1. The input is validated.
2. A new recipe object is pushed into the existing `recipes` array.
3. The statistics are recalculated.
4. The filters are reset so the new card is visible.
5. The recipe list is rendered again.
6. The form is cleared.
7. Focus returns to the recipe-name field.

The calorie value is included in the new recipe object and immediately contributes to the total-calorie statistic.

The vegetarian toggle controls the new recipe's `isVegetarian` value. When selected, the new card receives the vegetarian label and the vegetarian statistic increases immediately.

### Temporary browser state

Added recipes are stored only in the JavaScript array in the current browser session.

- No local storage is used.
- No database is used.
- No data is sent to a server.
- Refreshing the page restores the original 15 recipes.

## Data model

Every recipe follows this structure:

```javascript
{
    name: "Oatmeal with Banana",
    category: "Breakfast",
    prepTime: 10,
    calories: 280,
    isVegetarian: true
}
```

| Property | Type | Meaning |
|---|---|---|
| `name` | String | Recipe name |
| `category` | String | Breakfast, Lunch, Dinner, or Snack |
| `prepTime` | Number | Preparation time in minutes |
| `calories` | Number | Calorie value entered for the recipe |
| `isVegetarian` | Boolean | Whether the recipe is vegetarian |

The array is declared with `const`, which prevents replacing the entire array. Its contents can still be changed with methods such as `push()`.

## JavaScript walkthrough

This section follows the JavaScript in `dashboard.html` from top to bottom. JavaScript and Java are different languages; this project uses JavaScript because it runs directly in the browser.

### 1. Strict mode

The script begins with:

~~~javascript
"use strict";
~~~

Strict mode makes JavaScript report certain mistakes instead of silently accepting them. For example, accidentally assigning a value to a variable that was never declared will cause an error.

### 2. The users array

The first array contains the demo accounts:

~~~javascript
const users = [
    {
        email: "alex@example.com",
        password: "recipe123",
        name: "Alex"
    }
];
~~~

Important concepts:

- `const` creates a variable that cannot be reassigned.
- Square brackets create an array.
- Curly braces create an object.
- Each user object contains three properties: `email`, `password`, and `name`.
- The array gives the login listener a collection of accounts to search.

This is suitable for a demonstration, but real passwords must never be stored in front-end JavaScript.

### 3. The recipes array

The `recipes` array is the application's main data source:

~~~javascript
const recipes = [
    {
        name: "Oatmeal with Banana",
        category: "Breakfast",
        prepTime: 10,
        calories: 280,
        isVegetarian: true
    }
];
~~~

Every dashboard feature reads this array:

- `updateStatistics()` calculates its totals.
- `displayRecipes()` converts its objects into cards.
- `filterRecipes()` creates a smaller list from it.
- The add-recipe listener pushes new objects into it.

Although `recipes` uses `const`, this is valid:

~~~javascript
recipes.push(newRecipe);
~~~

`const` prevents replacing the array with a different value. It does not freeze the contents of the array.

### 4. Selecting HTML elements

The next group of statements connects JavaScript to HTML elements:

~~~javascript
const loginView = document.getElementById("login-view");
const loginForm = document.getElementById("login-form");
const searchInput = document.getElementById("searchInput");
const recipeList = document.getElementById("recipeList");
~~~

`document` represents the current webpage. `getElementById()` searches that page for an element with the matching `id`.

Saving each element in a variable makes it easy to:

- Read input values.
- Listen for user actions.
- Change displayed text.
- Hide or reveal a view.
- Insert generated recipe cards.

If an ID in JavaScript does not match an ID in the HTML, the result is `null`, and later operations on that variable will fail.

### 5. Showing login errors

The login error helper is:

~~~javascript
function showError(message) {
    errorMessage.textContent = message;
    errorMessage.hidden = message === "";
}
~~~

`textContent` safely changes the text inside the error element.

The comparison `message === ""` returns:

- `true` when the message is empty, so the error is hidden.
- `false` when a message exists, so the error is visible.

This helper avoids repeating the same DOM instructions throughout the login code.

### 6. Handling login submission

The login code listens for the form's `submit` event:

~~~javascript
loginForm.addEventListener("submit", function (event) {
    event.preventDefault();
});
~~~

`preventDefault()` stops the browser from submitting the form and refreshing the page. This lets JavaScript control what happens.

The input values are then read:

~~~javascript
const email = emailInput.value.trim().toLowerCase();
const password = passwordInput.value;
~~~

- `.value` reads what the user typed.
- `.trim()` removes spaces from the beginning and end.
- `.toLowerCase()` makes email comparison case-insensitive.

The script searches for a matching user:

~~~javascript
const matchedUser = users.find(function (user) {
    return user.email === email && user.password === password;
});
~~~

`find()` checks users one at a time. It returns the first matching user object, or `undefined` when no user matches.

The `&&` operator means both conditions must be true:

1. The email matches.
2. The password matches.

When a match exists, the views are switched:

~~~javascript
loginView.hidden = true;
dashboardView.hidden = false;
searchInput.focus();
~~~

No navigation occurs. Both views are already in the same HTML file. The `hidden` property controls which one is displayed.

When the credentials are incorrect, the script:

- Displays an error.
- Clears the password.
- Returns keyboard focus to the password input.

### 7. Handling logout

The logout button has a `click` listener:

~~~javascript
logoutButton.addEventListener("click", function () {
    dashboardView.hidden = true;
    loginView.hidden = false;
    loginForm.reset();
    showError("");
    emailInput.focus();
});
~~~

`reset()` restores the form controls to their original values. The two views are swapped again without changing the URL.

### 8. Calculating statistics with reduce

`updateStatistics(recipeList)` accepts an array of recipes. It uses `reduce()` to turn the whole array into one totals object:

~~~javascript
const totals = recipeList.reduce(function (accumulator, recipe) {
    accumulator.totalPrepTime =
        accumulator.totalPrepTime + recipe.prepTime;

    accumulator.totalCalories =
        accumulator.totalCalories + recipe.calories;

    if (recipe.isVegetarian === true) {
        accumulator.vegetarianCount =
            accumulator.vegetarianCount + 1;
    }

    return accumulator;
}, {
    totalPrepTime: 0,
    totalCalories: 0,
    vegetarianCount: 0
});
~~~

The parameters mean:

- `accumulator` stores the running totals.
- `recipe` is the current recipe being processed.
- The object after the callback supplies the initial zero values.

After reducing, the average is calculated only when the array is not empty:

~~~javascript
let averagePrepTime = 0;

if (recipeList.length > 0) {
    averagePrepTime =
        totals.totalPrepTime / recipeList.length;
}
~~~

This check prevents division by zero.

The results are formatted and inserted into the page:

- `toFixed(1)` displays one decimal place.
- `toLocaleString()` adds number separators such as the comma in `5,040`.
- `textContent` updates the statistic cards.

### 9. Escaping user-entered names

Recipe cards are generated as HTML strings. The `escapeHtml()` function converts special characters in a user-entered name into safe HTML entities:

~~~javascript
function escapeHtml(text) {
    return text
        .replaceAll("&", "&amp;")
        .replaceAll("<", "&lt;")
        .replaceAll(">", "&gt;")
        .replaceAll('"', "&quot;")
        .replaceAll("'", "&#039;");
}
~~~

For example, a less-than sign is displayed as text rather than being treated as the beginning of an HTML tag.

### 10. Rendering recipe cards with map

`displayRecipes(recipesToDisplay)` receives the exact array that should currently appear.

It first updates the count:

~~~javascript
resultCount.textContent = recipesToDisplay.length;
~~~

If the array is empty, the function displays a message and uses `return` to stop:

~~~javascript
if (recipesToDisplay.length === 0) {
    recipeList.innerHTML = "No recipes found.";
    return;
}
~~~

For a non-empty array, `map()` converts every recipe object into a card string:

~~~javascript
recipeList.innerHTML = recipesToDisplay.map(function (recipe) {
    return "recipe card markup";
}).join("");
~~~

- `map()` returns a new array of HTML strings.
- `join("")` combines those strings without commas.
- `innerHTML` places the finished cards inside the recipe grid.

Two conditional values customize each card:

~~~javascript
const vegetarianLabel = recipe.isVegetarian
    ? "Vegetarian label"
    : "";

const calorieText = recipe.calories > 0
    ? " · " + recipe.calories + " kcal"
    : "";
~~~

These use the ternary operator:

~~~text
condition ? value when true : value when false
~~~

This is why vegetarian recipes receive a label and recipes with zero calories omit the calorie text.

### 11. Filtering the recipe array

`filterRecipes()` begins by reading the current controls:

~~~javascript
const searchText = searchInput.value.trim().toLowerCase();
const selectedCategory = categoryFilter.value;
const vegetarianOnly = vegetarianFilter.checked;
~~~

`.checked` returns `true` or `false` for a checkbox.

The `filter()` method tests every recipe:

~~~javascript
const filteredRecipes = recipes.filter(function (recipe) {
    const matchesName =
        recipe.name.toLowerCase().includes(searchText);

    const matchesCategory =
        selectedCategory === "All" ||
        recipe.category === selectedCategory;

    const matchesVegetarian =
        vegetarianOnly === false ||
        recipe.isVegetarian === true;

    return matchesName && matchesCategory && matchesVegetarian;
});
~~~

Important operators:

- `.includes()` checks whether the name contains the search text.
- `||` means either condition may be true.
- `&&` means every matching rule must be true.

The filtered array is not saved over the original array. It is sent to `displayRecipes()`, leaving all recipe data available for future searches.

### 12. Showing add-recipe errors

`showAddRecipeError(message)` updates and hides or reveals the add-form error element. It follows the same pattern as the login error helper.

Keeping login errors and recipe errors separate prevents one form from changing the other form's message.

### 13. Adding a recipe

The add form also listens for `submit` and prevents a page refresh.

The values are collected and converted:

~~~javascript
const name = recipeNameInput.value.trim();
const category = recipeCategoryInput.value;
const prepTime = Number(recipePrepTimeInput.value);
const calories = Number(recipeCaloriesInput.value);
const isVegetarian = recipeVegetarianInput.checked;
~~~

`Number()` converts the preparation-time and calorie strings into numbers.

The validation rejects:

- An empty name.
- A value that is not a finite number.
- A preparation time below one.
- A calorie value below zero.

`Number.isFinite()` ensures both numeric values are usable numbers.

The new object follows the same structure as the original recipes:

~~~javascript
const newRecipe = {
    name: name,
    category: category,
    prepTime: prepTime,
    calories: calories,
    isVegetarian: isVegetarian
};
~~~

The new object is added with:

~~~javascript
recipes.push(newRecipe);
~~~

The remainder of the listener:

- Resets the add form.
- Clears its error.
- Clears the search.
- Selects **All categories**.
- Turns off the vegetarian-only filter.
- Recalculates statistics.
- Renders the updated recipe list.
- Focuses the recipe-name field.

Resetting the filters ensures that the newly added recipe is immediately visible.

### 14. Connecting filter events

The three filter controls call the same function:

~~~javascript
searchInput.addEventListener("input", filterRecipes);
categoryFilter.addEventListener("change", filterRecipes);
vegetarianFilter.addEventListener("change", filterRecipes);
~~~

- The search input uses `input`, so results change as the user types.
- The select and checkbox use `change`.
- Reusing one function keeps all filtering rules synchronized.

### 15. Initializing the dashboard

The final two statements run when the page first loads:

~~~javascript
updateStatistics(recipes);
displayRecipes(recipes);
~~~

The first call calculates the initial summary. The second call creates all 15 starting cards.

These calls run even while the dashboard view is hidden, so the dashboard is already prepared when login succeeds.

### Main JavaScript pattern

The application repeatedly follows this pattern:

~~~text
User action
    ↓
Event listener reads the controls
    ↓
JavaScript changes data or chooses a filtered array
    ↓
A function updates the DOM
    ↓
The browser displays the new result
~~~

This is the central idea behind the whole project: the recipe array stores the state, and the rendering functions keep the visible page synchronized with that state.

## Essential functions

### `showError(message)`

Controls the login error message.

- Places the message inside `#error-message`.
- Hides the element when the message is empty.
- Reveals it when an error message exists.

### Login submit listener

The `submit` listener on `#login-form`:

1. Prevents the browser's default form submission.
2. Reads the email and password.
3. Finds a matching user with `users.find()`.
4. Hides `#login-view` on success.
5. Reveals `#dashboard-view`.
6. Shows an error and clears the password on failure.

### Logout click listener

The `click` listener on `#logout-button`:

- Hides the dashboard.
- Reveals the login view.
- Resets the login form.
- Clears previous errors.
- Focuses the email input.

### `updateStatistics(recipeList)`

Calculates the summary values using `reduce()`.

For each recipe, it:

- Adds `recipe.prepTime` to the total preparation time.
- Adds `recipe.calories` to total calories.
- Increases the vegetarian count when `recipe.isVegetarian` is true.

The average is calculated as:

```text
total preparation time / number of recipes
```

An empty array safely produces an average of `0.0`.

### `escapeHtml(text)`

Escapes special characters in recipe names before inserting them into generated card markup.

This prevents a user-entered recipe name from being interpreted as HTML.

### `displayRecipes(recipesToDisplay)`

Renders recipe cards into `#recipeList`.

It:

- Updates the visible result count.
- Displays an empty-state message when the list has no items.
- Uses `map()` to create the card markup.
- Uses `join("")` to combine the cards into one HTML string.
- Adds the vegetarian label conditionally.
- Omits calories when their value is `0`.

### `filterRecipes()`

Reads the current filter controls and creates a filtered array.

A recipe is included only when it passes all active conditions:

```text
name matches
AND category matches
AND vegetarian preference matches
```

The resulting array is passed to `displayRecipes()`.

### `showAddRecipeError(message)`

Controls the add-recipe validation message in the same way that `showError()` controls login feedback.

### Add-recipe submit listener

The `submit` listener on `#add-recipe-form`:

1. Prevents a page reload.
2. Reads and trims the name.
3. Reads the category.
4. Converts preparation time into a number.
5. Converts calories into a number.
6. Reads the vegetarian checkbox.
7. Validates the name, preparation time, and calories.
8. Creates a new recipe object.
9. Adds it with `recipes.push(newRecipe)`.
10. Resets the form and filters.
11. Calls `updateStatistics(recipes)`.
12. Calls `filterRecipes()` to render the updated list.
